# ADR-0035: Design system — Tailwind v4 + shadcn-svelte, teal on a cool-grey neutral

**Context:** The legacy app got a consistent admin look for free from Filament. The rebuild's `apps/web` had about a hundred lines of hand-written element CSS, and the next UI tickets — the app shell (#167), the auth pages (#171), the Master restyle (#172), then every domain CRUD after them — would each have invented their own buttons, tables and form states. They need one vocabulary to compose from, and rules that keep it consistent and accessible without a designer on every PR (#170).

**Options considered:**

- Plain CSS custom properties and hand-written Svelte components: no dependencies, but every primitive (dialog focus trap, select keyboard model, toasts) is ours to build and maintain.
- A packaged component library (Skeleton, Flowbite-Svelte): complete, but its look and markup are a dependency we style around rather than own.
- Tailwind v4 with the shadcn-svelte registry: components are copied into the repo on top of bits-ui's accessible headless primitives, themed entirely through CSS variables.

**Decision:** Tailwind v4 through `@tailwindcss/vite` (CSS-first config, no PostCSS or `tailwind.config`), with shadcn-svelte initialised as style `nova`, base colour `mist` (the CLI's cool grey; it no longer ships `slate`), theme `teal`, Inter Variable and Lucide icons. `apps/web/src/app.css` is the single source of tokens; `/design-system` is the living reference. The rules:

1. **Semantic tokens only.** Pages and components colour with token utilities — `bg-primary`, `text-muted-foreground`, `border-border` — never raw hex/OKLCH or palette classes like `bg-teal-600`. A new colour need is a new token, defined in both `:root` and `.dark`.
2. **The registry is vendored, not forked.** `$lib/components/ui` is written by `shadcn-svelte add` and stays re-addable: system-wide adjustments go in `app.css` (tokens, the base layer) or ESLint config, not in those files. VMB-specific composition — `HeroIcon` now; `StatusPill`, `PageHeader`, `EmptyState` as their tickets need them — lives in `$lib/components`. `$lib/components/movingicons` (rule 3) is a third case: vendored by the same CLI, but deliberately patched after generation, so re-running `add --overwrite` there needs the patch reapplied.
3. **Icons are Lucide**, imported per icon (`@lucide/svelte/icons/<name>`). The Heroicons names legacy stores in `divisions.icon_name` and `roles.icon_name` render through `HeroIcon`, which maps known names to their Lucide equivalent and draws a neutral fallback for the rest. Decorative icons are `aria-hidden`; an icon-only button carries an `aria-label`. Where motion carries meaning — copy confirmed, a save succeeded, a refresh in progress, a settings panel opening — the icon is a vendored [moving icons](https://movingicons.dev) component (`@jis3r/icons`, MIT, pure CSS) in `$lib/components/movingicons`, added with `npx shadcn-svelte@latest add https://www.movingicons.dev/r/<icon>.json` and patched by hand: the wrapper `<div>` becomes a `<span>` (valid inside `<button>`/`<a>`), the forced `role="img"`/`aria-label` is replaced with `HeroIcon`'s contract (`aria-hidden` by default, labelled only when given a `label` prop), and the built-in hover self-trigger is removed so the parent control drives the animation through an `animate` prop. Moving icons are for state-change feedback only, never a decoration loop — everything else stays static Lucide (research: `docs/research/icon-set-and-animated-icons.md`).
4. **Forms** use the registry's formsnap `Form.*` parts with Superforms and the shared Zod schemas (ADR-0007): a visible label on every field, errors under the field they belong to, one primary action per form.
5. **Data** renders in the registry `Table` (which scrolls horizontally on narrow screens); numeric columns are right-aligned `tabular-nums`, codes are `font-mono`. Status is text plus tone, never colour alone.
6. **Accessibility is a per-PR gate:** text contrast ≥ 4.5:1 against its surface; a visible focus indicator (the teal border and ring); 44px targets on touch pointers; `prefers-reduced-motion` honoured; a keyboard path through every dialog, select and menu. Reduced motion has two halves. CSS `animation` and `transition` are collapsed globally in the base layer. Svelte's `transition:`/`in:`/`out:`/`animate:` and `Tween`/`Spring` run on the Web Animations API or JavaScript, as do JS libraries (Motion, Lottie, Rive), so the CSS rule never reaches them: each use reads `prefersReducedMotion` from `svelte/motion` and drops to duration 0, or no transition, when it is `true`. Because the global rule freezes a spinner after one frame, a loading indicator always carries text ("Loading…") and never relies on motion to read as loading.
7. **Dark mode** is a `.dark` class on an ancestor. The token map is complete for both schemes now; the toggle (`mode-watcher`) ships with the app shell (#167).

Three generated tokens were hand-tuned to meet rule 6, each marked in `app.css`: light `--muted-foreground` darkened from L 0.56 to 0.53 (4.15:1 → 4.70:1 on the `muted` surface); `--ring` set to the brand teal instead of grey, so the focus border reads 5.4:1; and dark `--primary` lightened to teal-500 with dark text, because the generated teal-800 read 2.6:1 as link text on the dark background (now 8.1:1, and 6.0:1 as a button fill). Touch targets are handled the same way: the registry is desktop-dense (32px controls, above WCAG 2.2 AA's 24px minimum), and a `pointer: coarse` rule in the base layer raises buttons, inputs and select triggers to 44px.

**Trade-offs:** Owning the component source means registry updates are pulled deliberately (re-run `add --overwrite` and review the diff) rather than arriving with a version bump — the cost of being able to read and adjust every primitive. Tailwind puts styling in markup, which is noisier to read but removes the naming and dead-CSS problems a hand-written stylesheet accumulates across a dozen CRUD modules. Inter adds a self-hosted variable font — 48 kB of woff2 for the Latin subset, other scripts fetched only when a page uses them — for consistent figures across platforms. One known exception to rule 6: input and card borders use shadcn's light `--input`/`--border` (1.25:1 against white), so a field's boundary is not 3:1 on its own; fields are identified by their visible labels instead, and this is revisited if an audit requires 3:1 field boundaries. Tailwind's preflight resets the element defaults the not-yet-restyled pages relied on, so `app.css` carries a scoped legacy layer restoring them (never applied to registry elements); each rule is deleted as the pages using it move onto the design system in #171 and #172.

# ADR-0058: The merge gate reads the review round, and Sourcery is scoped by its weekly budget

**Context:** PR #487 (2026-10-18) added Sourcery and CodeRabbit as free on-request reviewers: a build posts `@sourcery-ai review` and `@coderabbitai review` after its first green `Verify`, answers the findings, then runs `scripts/merge-gate.sh`. The gate read check runs only, and a reviewer's review is not a check. The same day PRs #485 and #486 merged at 11:44 UTC; Sourcery's reviews landed at 11:46 and 11:48 with three Medium findings, which reached `master` unanswered. Of the five builds launched that day, four ended their turn after `/code-review` or `/security-review` without opening or watching their PR, so no unattended build had yet posted an ask. Sourcery's Open Source plan allows 250,000 diff characters per developer per rolling week, not pooled, and every PR here is authored by `vmb-agent`; the day's three `standard` PRs measured 54,000, 45,000 and 66,000 characters after Sourcery's path filters, against five to thirteen merged PRs a day. CodeQL default setup was on since that morning, and the `master` ruleset required only `Verify`.

**Options considered:**

- **Keep the round as an instruction and trust the build's timing.** The docs already said to ask and to answer every finding; two PRs merged ahead of their reviews on the first day, and prose had not changed polling behaviour in six threads either.
- **Make the reviews required status checks.** Neither bot reports a check the ruleset can require, and Sourcery's silence on an exhausted budget would read as a pass.
- **Let the gate read the round.** Chosen. The gate already fetches the PR; one more field set (comments, reviews) and one GraphQL call (review threads) let it see the asks, the answers and the unanswered threads. `scripts/merge.sh` becomes the one merge path, so the gate runs for every merge, not only the night loop's.
- **Ask Sourcery on every PR.** Rejected: the budget would run out by the third day of each week and the rest of the week's PRs would get no Sourcery review while the loop read silence as clean.

**Decision:**

- `scripts/merge-gate.sh` fails a `standard` or `complex` ticket's PR unless a trusted author asked CodeRabbit and CodeRabbit submitted a review after the latest ask; the same for Sourcery when the ticket is `complex` or the PR touches `apps/api/` or `packages/db/`. A rate-limit reply is named and is not a review. Every review thread a reviewer bot opened must be resolved or answered by `ubeann` or `vmb-agent`. `Verify` must have reported, and `CodeQL` when the PR changes a `.ts`, `.tsx`, `.js`, `.mjs` or `.cjs` file or a workflow or action under `.github/`.
- `scripts/merge.sh <pr>` is the one way a PR is merged: the gate, then ready and squash. `--owner-approved "<who, where, when>"` records the owner's call as a PR comment, with the gate's reasons, before merging past a FAIL.
- Sourcery is asked on `complex` tickets and on diffs touching `apps/api` or `packages/db`; CodeRabbit on every `standard` and `complex` ticket. The review table in `docs/agents/model-routing.md` says so.
- A Claude Code `PreToolUse` hook (`scripts/check-bash-wait.sh`) refuses a Bash command that waits by `sleep`, `gh pr checks --watch`, `gh run watch` or a shell loop over `gh`, so a thread hands the waiting to `watch_pull_request` and its notifications.
- The `master` ruleset still requires `Verify` only. A docs-only PR produced no `CodeQL` check run in the week before default setup was enabled, and no docs-only PR has run since, so whether a required `CodeQL` check would block one is not yet observed; the gate's path-scoped rule covers code changes meanwhile. Add it to `scripts/master-ruleset.sh` once a docs-only PR shows the check reporting.

**Trade-offs:** A `standard` PR now waits for CodeRabbit's review before it can merge, a few minutes after the first green `Verify`, and a PR on an API or DB path waits for Sourcery's too; a reviewer that stays silent parks the PR for the owner rather than letting it through. That is the cost of the review being real. Sourcery's view of web-only changes is given up on `standard` tickets to keep its budget for the paths where a bug costs most. The hook refuses a few legitimate shapes (a loop over `gh api` that is not a wait) and names the alternative; the script a thread would have written can still sleep inside itself. The ruleset gains nothing until the CodeQL question is answered, which keeps one observation on the owner's list.

# ADR-0029: `app` on every environment branch, previews named for their PR, and a local database per developer

**Context:** The Neon project holds `production` and per-PR preview branches (ADR-0019, ADR-0028). Its production branch carries two databases: `vmb`, which the app migrates and the production Worker points at, and `neondb`, Neon's project-creation default, which nothing chose. Three problems met here. The committed fnox `DATABASE_URL` — the local tooling's connection string — resolved to `neondb` on `production` (ADR-0027 recorded it), so the local default target was a production-branch database and `db:seed`, which truncates every application table, would have wiped it; ADR-0028 left that open in its own consequences ("Local development still has no data environment… Open, and separable"). Second, a second database on every branch is not free: it is copied into every branch forked from a parent that has it, and `neon branches create` declines to print a connection URI when a parent holds more than one database. Third, the preview alias was slugged from the source branch, and the branches agents and worktree tools mint (`t3code/...`) are tool-authored noise while the pull request title is the description a human wrote; the alias is decoration — cleanup keys on the `pr<N>-` prefix and the `pr-<N>` Neon branch name — so it can be sourced from the better text.

**Options considered:**

- **Database name: keep `vmb`.** Costs nothing, but leaves the database named after the product while the environment lives in the branch name. **Rename to `app`.** Environment-agnostic: the same name on every branch, so a connection string differs only by host and a doc can say "the `app` database" without qualifying the environment. Chosen.
- **`neondb`: leave it as the default branch's second database.** Rejected: it is a database nothing migrates, it was the accidental local target, and it costs a copy on every fork. **Drop it, and keep no standing helper.** Chosen; a future rename creates a throwaway (`CREATE DATABASE rename_helper`) because Postgres will not rename the database you are connected to.
- **Local target: a standing dev branch.** Rejected by ADR-0028 for drift and upkeep. **Point local development at a database on `production`.** Rejected: the hazard above, and `db:seed` would wipe production-branch rows. **A local Postgres.** Rejected: `packages/db/src/client.ts` talks to Postgres through `@neondatabase/serverless` over HTTP (`drizzle-orm/neon-http`), so a plain local Postgres cannot serve the API without a Neon-protocol proxy, Docker and dev-only driver configuration. **A per-developer branch, created and seeded on demand.** Chosen.
- **The per-developer URL: the committed fnox store, or a per-developer overlay.** A shared encrypted file cannot hold a value that differs per developer without every developer's branch password landing in the shared store. Chosen: the gitignored `fnox.local.toml` overlay (fnox merges it over `fnox.toml`), using fnox's `plain` provider — right for a local, unshared value.
- **Preview alias source: the branch, or the title.** The branch is stable but often tool-authored; the title describes the PR but is editable. Chosen: the title, falling back to the branch and then the number — safe because nothing that outlives a run is derived from the slug.

**Decision:** Branch = environment; database = `app`; one name everywhere.

- The application database is **`app`** on every environment branch — `production`, every `pr-<N>` preview, and every developer's local branch. `vmb` is renamed to `app`; `neondb` is dropped and nothing replaces it.
- **Local development runs on a per-developer branch** (`dev-<slug>`), forked from `production`, migrated and seeded by `scripts/dev-db.sh`. `up` creates or reuses it, refreshes its expiry, writes its connection string into `fnox.local.toml`, and runs `db:migrate` + `db:seed`; `--reset` recreates it; `down` deletes it; `status` reports it; `list` audits what exists. It expires `DEV_DB_EXPIRES_DAYS` (default 90, `0` for none) after its last `up`, so the TTL is a safety net for a branch nobody uses rather than a deadline under one in daily use. Because it is seeded, it holds deterministic fixtures rather than production rows — the same data policy a preview has (ADR-0019). `DATABASE_URL` leaves the committed fnox store entirely, so no default can point at `production` again.
- **Preview aliases are named for the PR**: `pr<N>-<slug>`, where the slug is the title with its Conventional Commit prefix stripped, falling back to the branch name and then `pr-<N>`; the whole alias is capped at 28 characters so it fits Cloudflare Pages' branch-alias limit and `<alias>-vmb-api` stays inside its 63-character DNS label, and `scripts/preview-identifiers.test.sh` pins the cases in CI. **Cloudflare owns the Pages branch alias**: it truncates to 28 and appends a short suffix when that alias is already taken (measured on PR #156 — the posted 54-character alias returned 404 at the computed address, the truncated `…-an` 200, and a later run that collided with it got `…-an-15b2`), so `preview.yml` posts the web URL `wrangler` reports rather than one derived from the alias. The Pages prefix (`pr<N>-`) and the Neon branch name (`pr-<N>`) stay number-keyed, so a retitle cannot orphan anything.
- The preview comment names the database, so an environment is self-describing.

**Trade-offs:** The rename is a one-way door for connection strings: the production Worker secret, the fnox store, the workflows and four ADRs move in one change, and a child branch does not inherit a rename (copy-on-write), so every existing `pr-*` branch is deleted rather than migrated and a preview run in the window between the rename and the merge fails loudly until it is re-run. A per-developer branch costs a Neon branch per developer and a project-scoped API key on each machine — in exchange local data is disposable, deterministic and never production's, and `db:seed` can be run without thinking about which database it lands on. A title-derived alias moves when a title is edited: the URL changes on the next push, the superseded Pages deployment is reaped by the `pr<N>-` prefix on that same run, and the old Workers alias lingers until Cloudflare LRU-prunes it, since aliases are not deleted one by one (ADR-0019). That is acceptable because the alias was never a key and the comment is updated on the same run. Dropping `neondb` costs a throwaway database at the next rename and buys back `neon branches create`'s connection-URI output. The first `up` on a fresh branch replays whatever `production`'s migration journal is behind by — measured at 151–182 s (#131) — which is a one-off per branch, not per session.

**Consequences:**

- The ops runbook, in order, with the code change merged around it (the window is minutes; a failed preview re-runs):
  1. `ALTER DATABASE vmb RENAME TO app` on `production`, connecting via `neondb` and terminating other connections first. Renaming preserves data, schemas, grants and per-database settings — the same OID — so ADR-0027's `timezone = 'UTC'` declaration survives.
  2. `wrangler secret put DATABASE_URL --name vmb-api` with the renamed connection string; the production Worker is the only consumer that must move immediately.
  3. `DROP DATABASE neondb` on `production`. If it refuses with an open session, `DROP DATABASE neondb WITH (FORCE);` — the holder is usually a pooled server connection left by the old local `DATABASE_URL` (`neondb` on the `-pooler` host), and terminating it is fine because nothing should connect there any more.
  4. Delete every existing `pr-*` branch so previews recreate against `app`; one that keeps `vmb` fails its next migration.
  5. Verify in a fresh session: `SELECT current_setting('TimeZone')` is `UTC`, and `/health` answers.
- Local development: `scripts/dev-db.sh up` (usage in the script header), with `NEON_API_KEY` and `NEON_PROJECT_ID` in `fnox.local.toml`. The script hands the URL to its own `db:migrate` and `db:seed` runs directly; for anything you run by hand, go through fnox (`fnox exec pnpm --filter @vmb/db db:seed`) so the overlay's `DATABASE_URL` reaches it, and `apps/api`'s `predev` exports it into `.dev.vars` for `wrangler dev`.
- The cutover rehearsal (ADR-0028) passes its own throwaway branch's connection string explicitly; `$DATABASE_URL` is a developer's local branch now and must not be its target.
- `scripts/rotate-fnox-age-key.sh` no longer prompts for a connection string, and its verification reads a key that is still in the store.
- ADR-0027's `neondb` and local-development sentences are superseded in part; ADR-0019's alias paragraph and its `database: vmb` pin are updated in place; ADR-0028's open local-environment consequence is closed here.
- #131 is unaffected: a CI-maintained preview parent, if chosen, is a branch carrying `app` like any other.

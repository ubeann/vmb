# ADR-0047: Client hardening — CSP and security headers, not obfuscation

**Amended by #321:** point 7 enables `trustPolicy` and gates CI on registry signatures. It had deferred both.

**Context:** The owner asked whether Tailwind class names or the client bundle should be obfuscated to harden the client. Nothing protects the client today: apps/web sets no Content-Security-Policy and no security headers, there is no `_headers` file, and vmb-api sets no `secureHeaders`. Authorization already lives on the server (the `hooks.server.ts` gate, `requireSession` and the permission checks on vmb-api, ADR-0045), so everything shipped to the browser is public by design. Research: `docs/research/client-side-hardening.md`, with the browser behaviour tested in Chromium, Firefox and WebKit on 2026-10-05.

**Options considered:**

- Class-name mangling (Tailwind/PostCSS plugins) or JS obfuscation — rejected. OWASP treats obscurity as no control, and nothing in the bundle is secret. It would break shadcn-svelte's class contracts and test selectors, make stack traces and CSP reports harder to read, and add a build step that Tailwind v4's Vite plugin supports poorly.
- A strict CSP with no `'unsafe-inline'` for styles — rejected for now. Server-rendered `style="…"` attributes (etched scenes, swatches, password bar, `app.html`) are blocked, hydration does not repair them, and bits-ui's scroll-lock reset (`body.setAttribute("style", …)`) leaves the page frozen after a dialog closes in Chromium and WebKit.
- A nonce-based CSP for scripts, `'unsafe-inline'` for style attributes only, plus standard security headers — chosen.

**Decision:**

1. **No obfuscation** of class names or bundles.
2. **CSP through SvelteKit's `kit.csp`**, `mode: "auto"` (nonces, since nothing is prerendered):
   - `script-src 'self'` plus SvelteKit's per-request nonce. `'strict-dynamic'` is trialled later in report-only, because SvelteKit's modulepreload links carry no nonce.
   - `style-src-elem 'self'` plus the hash of mode-watcher's `* { transition: none }` sheet, which it appends while the scheme changes; a test re-derives the hash from the installed package. `style-src-attr 'unsafe-inline'`, and `style-src 'self' 'unsafe-inline'` as the fallback for Safari before 26.2.
   - `default-src`, `img-src`, `connect-src`, `base-uri` and `form-action` set to `'self'`; `font-src 'self' data:`, because Vite inlines font subsets under 4 kB; `object-src 'none'`; `frame-ancestors 'none'`.
   - Svelte 5 transitions use the Web Animations API, which CSP does not govern, so ADR-0040's motion toolset needs no exception.
3. **Inline scripts get the nonce.** The `app.html` script carries `nonce="%sveltekit.nonce%"` and takes over mode-watcher's FOUC script (`disableHeadScriptInjection`), since SvelteKit cannot pass the nonce to a component. The client sets zod's `jitless`, so its `new Function` probe stops filing a violation on every load.
4. **Report-only first.** The policy ships in `reportOnly`, with `report-to` (plus a `Reporting-Endpoints` header) and the deprecated `report-uri` for older browsers. Reports go to a same-origin `POST /csp-report` route on apps/web, which logs a size-capped summary, with query strings stripped, to Workers logs. The route is public and unauthenticated by necessity. Move the policy to `directives` after at least a week of production reports with no unexplained violations, keeping a tighter variant in `reportOnly`.
5. **Security headers from `handle`**, because Cloudflare Pages' `_headers` does not reach responses from the Pages Function: HSTS `max-age=31536000; includeSubDomains` (no `preload`, which is hard to undo), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, a `Permissions-Policy` disabling camera, microphone, geolocation, payment and USB, `Cross-Origin-Opener-Policy: same-origin`, and `X-Frame-Options: DENY` for browsers without `frame-ancestors`. `apps/web/_headers` sets the transport headers on static assets; adapter-cloudflare refuses a `_headers` in `static/` and copies the project-root file into its output. The gate's thrown 303 to `/login` skips `handle`'s post-`resolve` code; that is accepted, because a bodiless redirect needs none of these and `/login` sets HSTS on the next response.
6. **vmb-api** uses Hono's `secureHeaders()`, with `X-Frame-Options: DENY` and `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, per OWASP's REST guidance.
7. **pnpm supply chain:**
   - Set `minimumReleaseAge: 1440` explicitly, which makes pnpm 12's default strict, and give Dependabot's npm updates a matching one-day `cooldown`.
   - `trustPolicy: no-downgrade` fails an install whose release has weaker provenance than an earlier one. `trustPolicyExclude` names two reviewed releases: `chokidar@4.0.3` and `undici-types@6.21.0`. Both kept their usual maintainer after provenance lapsed, and their dependents pin them.
   - CI gates on `pnpm audit signatures`. Known advisories are not gated per PR, since a newly published one would turn unrelated PRs red and stall the merge gate. Dependabot alerts and security updates track them instead.

**Trade-offs:** `style-src-attr 'unsafe-inline'` leaves CSS injected into an existing `style` attribute possible. Svelte escapes attribute values, `url()` loads still hit `img-src`, and injected `<style>` elements, the attribute-selector exfiltration vector, stay blocked. Removing it would mean rewriting every server-rendered style attribute and patching bits-ui, which is not worth it before the reports show what else breaks. The report endpoint is an unauthenticated log sink; size caps bound the cost, and it can move behind rate limiting if it is abused. Style violations only appear in production builds, because SvelteKit loosens styles in dev, so report-only has to run on a deploy, not locally. In return, an injected script cannot run without the per-request nonce, the app cannot be framed, and a release younger than a day, or one with weaker provenance than its predecessors, fails the install instead of shipping. That last check costs upkeep: a release whose provenance lapsed needs reviewing and adding to `trustPolicyExclude` before any install passes, and the list only grows until its dependents move past those releases.

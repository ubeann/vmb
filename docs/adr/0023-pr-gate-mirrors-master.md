# ADR-0023: The PR gate mirrors the master gate

**Context:** `ci.yml` skipped CI on docs-only pull requests (`paths-ignore: [docs/**, **.md]`), while `push` to `master` carried no path filter and the `Verify` job ran `prettier --check .` over the whole repo. A docs-only PR was therefore unchecked, yet its merge re-ran the repo-wide check on `master` — and a red `Verify` skips `deploy`, which `needs: build-and-test`. #58 merged an ADR whose markup prettier rejects; `master`'s `Verify` went red and `Release` was skipped, silently blocking the production deploy for three and a half hours until #60 fixed the formatting. Separately, #59 failed `Verify` on an ADR it never touched, and the log read as a typecheck failure because turbo cancels in-flight tasks around the real one.

**Options considered:**

- Remove the path filter so every PR runs the same gate as `master` — chosen.
- Gate the heavy jobs on a changed-file check, so a docs-only PR runs only `format:check` and the workflow lints — rejected: turbo's remote cache already makes the code tasks free on a docs-only diff (the docs-only master run `35318173810` reported `Cached: 12 cached, 13 total`, `Time: 1.993s`), so the saving is near zero, and it breaks the invariant this ADR exists to establish.
- Scope `format:check` to the PR's changed files — rejected: a PR passes scoped, then `master`'s repo-wide run goes red, which is the #58 failure mode over again. Drift has to be caught somewhere, and the PR is the only place it is cheap.
- Drop markdown from prettier entirely (`.prettierignore`) — rejected: it reverses #48 (normalise the codebase to the shared prettier config) and gives up consistent ADR prose to avoid one class of failure the gate exists to catch.
- Leave docs-only PRs out of CI and accept master-side failures — rejected: that is the cause, not a mitigation.

**Decision:** A pull request runs the same gate a push to `master` runs, so nothing reaches `master` that a PR could have caught. No `paths-ignore` on the CI workflow, and `format:check` stays repo-wide in its own named `Format` step. The step, not a separate job, is deliberate: a job of its own would pay a second checkout, mise install, and `pnpm install` on every run merely to invoke prettier, and — because prettier needs `node_modules` — it cannot reuse the `install_args` trick that keeps the lint job fast. A named step still makes a formatting failure read as one instead of surfacing as a cancelled typecheck. `shellcheck` also covers `scripts/**/*.sh`, not only the shell inside workflow `run:` blocks; the lint job runs `find scripts -name '*.sh'` through it. Tracked in #61, with local pre-commit hooks split out to #62. One job remains conditional: `Release` deploys only when the push changed something the deployed artifact depends on, so a docs-only or ADR-only merge to `master` still runs `Verify` but skips the redundant deploy (issue #63). The gating path list is Preview's `paths` minus `.github/workflows/**` — a workflow edit is exercised by that PR's Preview run but cannot change the deployed artifact, so it must not force a deploy (a change to the deploy steps themselves therefore takes effect on the next code merge, not on the workflow-only merge that made it); reconciling the two lists is issue #70.

**Trade-offs:** Docs-only PRs now run the full gate, where they previously ran nothing — but the measured cost is runner setup (about 40 seconds for the `Verify` job), not tests, because turbo replays every code task from cache and only the repo-wide `format:check` misses. In return `master` cannot be turned red by something a PR was allowed to skip. The binding constraint this records is that any check which can fail on `master` must be checkable on a PR, so a check may not be conditioned on paths the `master` run does not also condition on. A local pre-commit hook is fast feedback only — bypassable and absent on a fresh clone — so it never substitutes for this gate. Enforcement is advisory: the repository is private on GitHub Free, where required status checks are unavailable (`branches/master/protection` returns 403), so a red `Verify` does not block a merge. Hard enforcement of commit-message and formatting conventions therefore rests on #62's `commit-msg` hook until the plan or visibility changes.

Gating the deploy adds one failure mode — a diff error or an unusable baseline could skip a needed release — and trades it for not redeploying byte-identical artifacts. The check fails open (any uncertainty deploys), so the residual risk is a missed saving, never a missed release. `Release` keeps `needs: build-and-test`, so a red gate still skips it exactly as before.

# ADR-0020: Dependabot PRs run a secret-free CI subset and skip Preview

**Context:** `.github/dependabot.yml` (issue #35) opens weekly grouped bump PRs, and the first batch (#36–#38) was born red for reasons unrelated to the bump. GitHub gives Dependabot-triggered workflow runs their own secrets store, separate from the Actions store, and this repo's Dependabot store is empty. `ci.yml` wraps its verify tasks in `fnox exec` with `FNOX_IF_MISSING: error`, so a Dependabot run dies decrypting the committed store with a missing `FNOX_AGE_KEY`; `preview.yml` dies earlier still, in `Resolve preview URLs`, on an empty `CLOUDFLARE_API_TOKEN` (evidence: CI [35213547325](https://github.com/ubeann/vmb/actions/runs/35213547325), Preview [35213547361](https://github.com/ubeann/vmb/actions/runs/35213547361)). A check that fails for a reason unrelated to the change is worse than no check — it trains everyone to ignore the result, which is what the Dependabot config existed to prevent.

**Options considered:**

- (a) Mirror the 7 Actions secrets into the Dependabot secrets store. Restores the full pipeline with no workflow change, but hands `CLOUDFLARE_API_TOKEN` (production deploy), `NEON_*`, and `FNOX_AGE_KEY` (which unlocks every dev secret in the committed fnox store) to a run whose whole purpose is to install and build freshly-bumped third-party code — the code most likely to be compromised.
- (b) Run a secret-free subset for Dependabot (install, lint, typecheck, build, and tests that need no secrets) and skip Preview for them.
- (c) Run the secret-free subset for everyone. Simpler and uniform, but drops the `fnox exec` validation human PRs currently get, so a broken fnox store or a secret-dependent build would not surface until deploy.

**Decision:** (b). In `ci.yml`, `build-and-test` gains a secret-free step running `pnpm turbo build test lint typecheck format:check`, while the existing `fnox exec` step is narrowed to the complement, so same-repo human PRs and `master` pushes keep the full path unchanged. In `preview.yml` the `preview` job is skipped for Dependabot PRs; it cannot be made secret-free because it needs Neon and Cloudflare. `cleanup.yml`'s delete job is skipped for them too: with Preview skipped no Neon branch is created, and its lookup would otherwise fail on an empty `NEON_API_KEY`.

"Dependabot" is detected by the triggering actor _or_ the pull request author (`github.actor == 'dependabot[bot]' || github.event.pull_request.user.login == 'dependabot[bot]'`, negated for the full path). The author term matters: a maintainer re-running a job, or pushing to the branch, sets the actor to the human, and actor alone would then flip that run — and its secrets — onto freshly-bumped code. On `master` pushes there is no pull request, so the author term is empty and the full path runs. A conditionally-skipped job concludes `skipped`, which GitHub treats as a success for a required check, so skipping Preview and Cleanup does not block a Dependabot PR from merging.

The secret-free run is not a weaker signal: the suite needs no secrets — every test mocks its database, and build/lint/typecheck/format read none — so a bump that breaks any of them still fails and a clean bump passes.

**Trade-offs:** A Dependabot PR loses the preview environment and any step that needs a secret, so a bump that breaks only at runtime — not at build, lint, or test — passes CI and first shows up in the post-merge production deploy. Accepted because the alternative exposes production deploy credentials and the fnox store key to bump code. A maintainer who wants the full path for a bump makes their own branch/PR (or tests the bump locally) instead of re-running the Dependabot PR, which stays secret-free by design. In return, a bump's check means what it says, and no production deploy credential is reachable from any run of a Dependabot-authored pull request. If a skipped step proves to matter, widen the subset deliberately and record that here.

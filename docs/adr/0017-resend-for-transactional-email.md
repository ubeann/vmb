# ADR-0017: Transactional email — Resend

**Context:** Signup now requires email verification (Better Auth's `emailAndPassword.requireEmailVerification`, on the stack decided in ADR-0012), so `apps/api` must send a transactional email containing the verification link. `apps/api` runs as a Cloudflare Worker (ADR-0003, ADR-0009), and that shapes the options: Workers *do* expose raw outbound TCP via the `connect()` API (`cloudflare:sockets`), but block outbound connections on port 25 — SMTP's port — by default. That, not a blanket lack of TCP, is what actually rules out conventional SMTP client libraries (nodemailer et al.): they dial SMTP servers on port 25, which Workers won't let through. Any sender must be reachable over HTTP from `fetch()` instead.

**Options considered:**
- SMTP relay via a Node SMTP client (nodemailer): the conventional web-app choice and probably what the legacy Laravel app used, but blocked outright by Workers' default port-25 restriction — not viable without a separate always-on relay service outside Workers.
- Resend (HTTP API, official Node SDK, typed error returns): works from Workers with no shim, and the SDK call shape is identical in dev and prod.
- Cloudflare Email Service (native `send_email` binding): no third-party vendor and no egress at all, but at the time of this decision it is in **public beta**, outbound sending requires a Workers **Paid** plan (this app runs on the free tier per ADR-0012's whole CPU-budget discussion), and the sending domain must use Cloudflare DNS. Rejected for now, not on principle — the isolation below is what keeps that door open once these constraints lift.
- MailChannels' free Workers integration: the historical "free email from Workers" answer, but that free program was discontinued in mid-2024, so it is not a live option.

**Decision:** Resend, called from one thin sender module (`apps/api/src/email.ts`) that wraps the verification email. `RESEND_API_KEY` and `EMAIL_FROM` are Worker bindings, with dev values via fnox (ADR-0011) and production values via `wrangler secret` / the dashboard like every other secret.

**Trade-offs:** Adds a third-party email vendor, which cuts against ADR-0009's Cloudflare-only bias and means one more secret to rotate and one more dashboard to watch. In exchange it is the shortest path to a working verification email on Workers, has no TCP constraint to design around, and its free tier comfortably covers an internal app's signup volume. The sender is deliberately confined to a single module so that swapping vendors is a one-file change — most plausibly to Cloudflare Email Service once it leaves Beta, which would also remove the vendor entirely.

**Known limitation, accepted:** Better Auth invokes the `sendVerificationEmail` callback inside `runInBackgroundOrAwait`, which catches and only logs failures when no `advanced.backgroundTasks.handler` is configured (confirmed by reading better-auth's installed dist source, not assumed from docs). A bad `RESEND_API_KEY` or a Resend outage therefore does not reach the user and does not block signup — it is visible only in Workers logs. This is Better Auth's by-design handling of email side effects, not a misconfiguration to be patched around. Mitigation: watch logs for `sendVerificationEmail: Resend request failed`, or wire a `backgroundTasks.handler` if silent failure becomes unacceptable.

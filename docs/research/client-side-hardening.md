# Client-side hardening for apps/web: CSP, security headers, supply chain

Researched 2026-10-05 against the lockfile's versions: SvelteKit **2.70.3**, Svelte **5.57.1**, adapter-cloudflare **7.2.9**, bits-ui **2.19.4**, mode-watcher **1.1.0**, Better Auth **1.7.7**, zod **4.6.5**, pnpm **12.4.1**. Local source reads used the copies installed in the main checkout. They are bits-ui 2.19.3 and Better Auth 1.7.6, and every line cited was re-checked on unpkg at the locked version. The browser behaviour claims marked **(tested)** come from a Playwright 1.63 run against Chromium 153, Firefox 155 and WebKit 26.6. Each test page was served with a real `Content-Security-Policy` header and checked with `getComputedStyle` (throwaway script, not committed).

## TL;DR

- Nothing is set today: no `kit.csp`, no security headers in `handle`, no `_headers` file, no `secureHeaders` on vmb-api (see [Current state](#current-state-of-the-repo)).
- **Scripts can be strict.** Use `kit.csp` with `mode: 'auto'` and `script-src 'self'`, and SvelteKit nonces its own inline boot script. Three things need fixing first:
  1. the inline `<script>` in `app.html` needs `nonce="%sveltekit.nonce%"`;
  2. mode-watcher's `{@html}` head script needs its own nonce, which SvelteKit cannot supply to components;
  3. zod's `new Function` probe raises a violation report on every load unless `jitless` is set.
- **Style attributes cannot be strict without breaking the app.** Server-rendered `style="…"` attributes (the etched scenes, swatches, password bar, and `app.html` itself) are blocked by any `style-src` without `'unsafe-inline'`, and so is bits-ui's `body.setAttribute("style", …)` reset. The reset failure leaves `overflow:hidden; pointer-events:none` on `<body>` in Chromium and WebKit after a dialog closes **(tested)**. Svelte 5 transitions themselves are **not** a problem: they use WAAPI, which CSP does not govern.
- **Practical style policy:** `style-src-attr 'unsafe-inline'`. Then either keep `style-src-elem 'self'` (SvelteKit adds a nonce; this breaks two cosmetic runtime `<style>` injections) or use plain `style-src 'self' 'unsafe-inline'`.
- **Headers must come from `handle`.** `_headers` does **not** apply to SSR responses on Pages, only to static assets.
- **Supply chain:** pnpm 12 already applies `minimumReleaseAge` 1440 by default, but not strictly. `allowBuilds` is already in place. No third-party scripts exist, so SRI does not apply yet.

**Recommended rollout**

1. **Report-only CSP.** Set `kit.csp.reportOnly` with the policy below, plus a same-origin report endpoint. Fix the three script issues (app.html nonce, mode-watcher, zod `jitless`). Watch the reports for a week across the auth, master and error pages.
2. **Headers.** Add a `handle` that sets HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` and COOP on SSR responses. Add an `apps/web/_headers` file (project root; adapter-cloudflare throws on `static/_headers`) with the same set for static assets, and `secureHeaders()` on vmb-api.
3. **Enforce.** Move the policy from `reportOnly` to `directives`, and keep a stricter variant in `reportOnly` (for example, no `'unsafe-inline'` for styles) to measure further tightening.

Candidate policy (SvelteKit config shape; SvelteKit adds the quotes and the nonce):

```js
// svelte.config.js — kit.csp
csp: {
  mode: "auto",
  reportOnly: {
    "default-src": ["self"],
    "script-src": ["self"],
    "style-src": ["self", "unsafe-inline"], // what Safari < 26.2 uses, as it ignores style-src-elem
    "style-src-elem": ["self"],             // SvelteKit appends its nonce + the "/* empty */" hash
    "style-src-attr": ["unsafe-inline"],
    "img-src": ["self"],                    // add data: only if reports show Vite-inlined assets
    "font-src": ["self"],
    "connect-src": ["self"],                // the browser only talks to apps/web (form actions)
    "object-src": ["none"],
    "base-uri": ["self"],
    "form-action": ["self"],
    "frame-ancestors": ["none"],
    "report-uri": ["/csp-report"],
    "report-to": ["csp"]
  }
}
```

## 1. SvelteKit `kit.csp`

- **Modes.** `'hash' | 'nonce' | 'auto'`. In `'auto'`, SvelteKit uses "hashes for prerendered pages, and nonces for dynamically rendered pages". "Using nonces with prerendered pages is insecure and therefore forbidden" ([config docs](https://svelte.dev/docs/kit/configuration#csp); [`public.d.ts:403`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/exports/public.d.ts#L403)). In the implementation, `use_hashes = mode === 'hash' || (mode === 'auto' && prerender)`, and one 128-bit random nonce is generated per response ([`csp.js:6-9`, `:370`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/csp.js#L370)). Prerendering throws if the mode is `'nonce'` or if `app.html` contains `%sveltekit.nonce%` ([`render.js:71-77`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/render.js#L71)). VMB prerenders nothing (no `prerender` export in `apps/web/src`), so `'auto'` behaves as `'nonce'` here.
- **What gets a nonce or hash.** Only what SvelteKit generates: its init script ([`render.js:584`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/render.js#L584)) and inlined CSS ([`render.js:325-326`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/render.js#L325)). Inlined CSS only exists with `inlineStyleThreshold > 0`, which VMB does not set. Manual scripts in `app.html` use the `%sveltekit.nonce%` placeholder ([config docs](https://svelte.dev/docs/kit/configuration#csp)). That placeholder is replaced only in the compiled `app.html` template ([`write_server.js:58`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/core/sync/write_server.js#L58)), not in component output. Components get no nonce API.
- **Which directives get augmented.** A nonce or hash is added to a directive only when that directive lacks `'unsafe-inline'` (or has `'strict-dynamic'` for scripts) ([`csp.js:149-173`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/csp.js#L149)). This matters because a nonce in a list makes browsers ignore `'unsafe-inline'`. When `style-src-elem` is set, SvelteKit also adds the hash of `/* empty */` ([`csp.js:221-234`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/csp.js#L221)).
- **Dev vs prod.** In dev, SvelteKit force-adds `'unsafe-inline'` to `style-src`, `style-src-attr` and `style-src-elem` so that Vite can inject `<style>` ([`csp.js:118-146`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/csp.js#L118)). **Style violations only show up in a production build** (`vite build` + `wrangler pages dev`, or a preview deploy).
- **`directives` vs `reportOnly`.** They are emitted as `content-security-policy` and `content-security-policy-report-only` response headers on SSR pages ([`render.js:607-616`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/render.js#L607)). A non-empty `reportOnly` **throws** unless it includes `report-uri` or `report-to` ([`csp.js:337-351`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/csp.js#L337)).
- **Prerendered pages.** The policy goes in a `<meta http-equiv>` tag instead of a header, and `frame-ancestors`, `report-uri` and `sandbox` are dropped ([config docs](https://svelte.dev/docs/kit/configuration#csp); [`csp.js:290`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/csp.js#L290); [`render.js:598`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/render.js#L598)). Report-only is not emitted at all for prerendered pages.
- **Scope.** CSP covers only HTML that SvelteKit renders (pages and its rendered error pages). It does not cover `+server` endpoints, static assets, or prerendered files, because "requests for static assets — which includes pages that were already prerendered — are _not_ handled by SvelteKit" ([hooks docs](https://svelte.dev/docs/kit/hooks#Server-hooks-handle)).
- **Adapter-cloudflare caveats.**
  - A per-request nonce means SSR HTML must not be edge-cached. Pages Function output is not cached unless you add caching. **UNVERIFIED** for the zone's own cache rules.
  - Cloudflare features that inject scripts conflict with a nonce policy. Rocket Loader needs `ajax.cloudflare.com`, Scrape Shield (email obfuscation) needs `'unsafe-inline'`, and Web Analytics needs `static.cloudflareinsights.com` plus `connect-src cloudflareinsights.com` ([Cloudflare CSP reference](https://developers.cloudflare.com/fundamentals/reference/policies-compliances/content-security-policies/)). Keep those features off for the Pages project.
- **`'strict-dynamic'`.** This is OWASP's recommended strict form ([CSP cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html)). SvelteKit's `<link rel="modulepreload">` tags carry no nonce ([`render.js:398`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/runtime/server/page/render.js#L398)). Under `'strict-dynamic'`, which ignores `'self'`, those preloads would probably be refused (a performance cost, not breakage). **UNVERIFIED.** Start with `'self'`, and trial `'strict-dynamic'` in `reportOnly`.

## 2. Svelte 5 transitions and `style-src`

- **Transitions use the Web Animations API, not `<style>`.** `animate()` builds keyframe objects from the transition's `css(t, u)` string and calls `element.animate(keyframes, { duration, fill: 'forwards' })` ([`transitions.js:415`, `:476`](https://github.com/sveltejs/svelte/blob/svelte%405.57.1/packages/svelte/src/internal/client/dom/elements/transitions.js#L415); keyframe conversion at [`:47-60`](https://github.com/sveltejs/svelte/blob/svelte%405.57.1/packages/svelte/src/internal/client/dom/elements/transitions.js#L47)). The only other style write is `element.style.overflow = 'hidden'`, a CSSOM property ([`:453`](https://github.com/sveltejs/svelte/blob/svelte%405.57.1/packages/svelte/src/internal/client/dom/elements/transitions.js#L453)). WAAPI animations applied under `style-src 'self' 'nonce-…'` in all three engines **(tested)**.
- **The SvelteKit docs note is stale for Svelte 5.** It says "most Svelte transitions work by creating an inline `<style>` element … you must either leave the `style-src` directive unspecified or add `unsafe-inline`" ([`public.d.ts:405`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/exports/public.d.ts#L405)). That describes Svelte 3/4. ADR-0040's choice of Svelte built-ins plus WAAPI and View Transitions therefore needs no `'unsafe-inline'`.
- **Component `<style>` blocks.** Svelte only appends a `<style>` element at runtime when compiled with `css: 'injected'` ([`css.js:27-31`](https://github.com/sveltejs/svelte/blob/svelte%405.57.1/packages/svelte/src/internal/client/dom/css.js#L27)). The default is `'external'` ([`validate-options.js:56`](https://github.com/sveltejs/svelte/blob/svelte%405.57.1/packages/svelte/src/compiler/validate-options.js#L56)), and SvelteKit emits component CSS as `.css` files.
- **`style:` directive and `style=` attribute.**
  - Server-side, both render as a markup `style="…"` attribute. A markup `style` attribute is a `'style attribute'` inline check, governed by `style-src-attr`, falling back to `style-src` ([CSP3 §6.1.15, §4.2.3](https://www.w3.org/TR/CSP3/#directive-style-src-attr)).
  - Nonces apply to elements, not attributes. Attribute hashes need `'unsafe-hashes'` ([CSP3 §8.3](https://www.w3.org/TR/CSP3/#unsafe-hashes-usage)), which does not work for dynamic values.
  - On the client, `set_style` writes `dom.style.cssText = …` ([`style.js:41`](https://github.com/sveltejs/svelte/blob/svelte%405.57.1/packages/svelte/src/internal/client/dom/elements/style.js#L41)) and the `style:` directive writes `dom.style.setProperty` ([`style.js:17-19`](https://github.com/sveltejs/svelte/blob/svelte%405.57.1/packages/svelte/src/internal/client/dom/elements/style.js#L17)). Both are CSSOM.
  - **Hydration does not repair a blocked SSR attribute.** While hydrating, `set_style` skips the write when the new value equals the attribute already in the DOM ([`style.js:37`](https://github.com/sveltejs/svelte/blob/svelte%405.57.1/packages/svelte/src/internal/client/dom/elements/style.js#L37)). The attribute is present but was never applied, so it stays unstyled until the value changes.
- **Static attributes in client templates.** Svelte builds templates through `<template>.innerHTML` ([`reconciler.js:23`](https://github.com/sveltejs/svelte/blob/svelte%405.57.1/packages/svelte/src/internal/client/dom/reconciler.js#L23)). Under strict `style-src`, static `style` attributes parsed that way were applied in Chromium and WebKit but **blocked in Firefox** **(tested)**. One example is SvelteKit's own route announcer, `style="position: absolute; … clip: rect(0 0 0 0)…"` ([`write_root.js:177`](https://github.com/sveltejs/kit/blob/%40sveltejs/kit%402.70.3/packages/kit/src/core/sync/write_root.js#L177)). In Firefox the page title would leak visibly after each navigation. **UNVERIFIED** end-to-end; inferred from the test.

**MDN conflicts with observed behaviour on `cssText`.** MDN lists `el.style.cssText = "…"` as blocked alongside `setAttribute("style", …)`, and `el.style.display = …` as not blocked ([MDN style-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/style-src#unsafe_inline_styles)). The CSP3 spec does not address CSSOM at all. In all three engines, under `style-src 'self' 'nonce-abc'` **(tested)**:

| Mechanism                               | Applied?    |
| --------------------------------------- | ----------- |
| Markup `style=""`                       | Blocked     |
| `setAttribute('style', …)`              | Blocked     |
| `el.innerHTML` with a `style` attribute | Blocked     |
| `<style>` without nonce                 | Blocked     |
| `<style nonce>`                         | Applied     |
| `style.cssText = …`                     | **Applied** |
| `style.setProperty` / `style.x =`       | Applied     |
| `element.animate()`                     | Applied     |

Adding `style-src-attr 'unsafe-inline'` unblocked every attribute case and left non-nonced `<style>` blocked.

## 3. Tailwind v4, shadcn-svelte and bits-ui

- **Tailwind v4 has no runtime.** `@tailwindcss/vite` compiles `app.css` at build time (`apps/web/vite.config.ts:2,21`). `tailwind-variants` and `cn` only build class strings. Neither creates any CSP surface.
- **bits-ui floating positioning** (Select, DropdownMenu): floating-ui's coordinates are merged into a `style` prop object ([unpkg bits-ui@2.19.4 `use-floating-layer.svelte.js:101-123`](https://unpkg.com/bits-ui@2.19.4/dist/bits/utilities/floating-layer/use-floating-layer.svelte.js)). Svelte writes that prop via `cssText` (CSSOM), which survived a strict `style-src` **(tested)**. Floating content is closed at SSR, so no markup attribute is involved.
- **bits-ui body scroll lock** (Dialog, Select, DropdownMenu): the lock sets `body.style.overflow/pointerEvents` via CSSOM, and the release resets with `documentObj.body.setAttribute("style", initialBodyStyle ?? "")` ([unpkg `body-scroll-lock.svelte.js:34`](https://unpkg.com/bits-ui@2.19.4/dist/internal/body-scroll-lock.svelte.js)). Reproducing that pattern under `style-src 'self'` left `overflow:hidden; pointer-events:none` on `<body>` in **Chromium and WebKit**; Firefox cleared it **(tested)**. That means a frozen page after closing any dialog. `style-src-attr 'unsafe-inline'` fixes it. This was not run through bits-ui itself; it is an inference from the identical primitive.
- **bits-ui PinInput** (VMB's `ui/input-otp`) appends `<style id="pin-input-style">` and `insertRule`s `::selection` and `:autofill` rules ([unpkg `pin-input.svelte.js:201-207`](https://unpkg.com/bits-ui@2.19.4/dist/bits/pin-input/pin-input.svelte.js)). A non-nonced `<style>` gets no sheet under a strict `style-src-elem`, and the code guards `if (styleEl.sheet)`, so the effect is cosmetic: selection and autofill colours show in the OTP boxes.
- **mode-watcher.**
  - It appends a non-nonced `<style>` (`* { transition: none !important }`) on each theme switch ([unpkg mode-watcher@1.1.0 `without-transition.js:16-23,48`](https://unpkg.com/mode-watcher@1.1.0/dist/without-transition.js)). Under a strict `style-src-elem` this is cosmetic: colours animate during the switch.
  - Its FOUC head script is emitted through `{@html \`<script${nonce}>…\`}` ([`mode-watcher-full.svelte:24-28`](https://unpkg.com/mode-watcher@1.1.0/dist/components/mode-watcher-full.svelte)). It takes a `nonce` prop, but SvelteKit cannot hand a component the per-request nonce (§1).
  - Fix: use `disableHeadScriptInjection` ([`mode-watcher.svelte:31`](https://unpkg.com/mode-watcher@1.1.0/dist/components/mode-watcher.svelte)) and move the class-setting logic into `app.html`'s existing inline script under `nonce="%sveltekit.nonce%"`.
- **Implication.** `style-src-attr 'unsafe-inline'` is required for VMB as built. The residual risk is CSS injected into an existing attribute. Svelte escapes attribute values, and `url()` loads still hit `img-src`. Without `'unsafe-inline'` in `style-src-elem`, injected `<style>` blocks (the attribute-selector exfiltration vector) stay blocked. OWASP's guidance is still to avoid `'unsafe-inline'` in `style-src` ([CSP cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html)).
- **Browser support for the split.** `style-src-attr` is supported in Chrome 75, Firefox 108 and Safari 15.4. `style-src-elem` is supported in Chrome 75 and Firefox 108, but only **Safari 26.2**, and older Safari falls back to `style-src` ([MDN browser-compat-data](https://github.com/mdn/browser-compat-data/blob/main/http/headers/Content-Security-Policy.json)). Hence `style-src` keeps `'unsafe-inline'` in the candidate policy.

## 4. Security headers on Cloudflare Pages

- **`_headers` does not reach SSR.** "Custom headers defined in the `_headers` file are not applied to responses generated by Pages Functions… the headers should be sent from the Pages Functions' `Response`" ([Cloudflare `_headers`](https://developers.cloudflare.com/pages/configuration/headers/)). The SvelteKit adapter docs say the same: `_headers` "will have no effect on responses dynamically rendered by SvelteKit… use server endpoints or the `handle` hook" ([adapter-cloudflare](https://svelte.dev/docs/kit/adapter-cloudflare)). Limits: 100 rules, 2,000 characters per line.
- **Where to set each set.** SSR pages get headers in `handle`, via `response.headers.set(...)` after `resolve` ([hooks docs](https://svelte.dev/docs/kit/hooks#Server-hooks-handle)). Responses with immutable headers, such as `Response.redirect()`, throw a `TypeError`, so guard or clone. Static assets (`/_app/immutable/*`, `static/*`) are served without the Worker via `_routes.json` ([adapter-cloudflare](https://svelte.dev/docs/kit/adapter-cloudflare)), so they need a `_headers` file. adapter-cloudflare throws if it finds one in `static/` and copies `apps/web/_headers` (the project root) into its output instead (`adapter-cloudflare/index.js:32-36,136-142` at 7.2.9; found while implementing).
- **The 303 redirect bypasses an after-`resolve` setter.** VMB's gate throws `redirect(303)` before `resolve` (`hooks.server.ts:27`), so code after `resolve` never runs for it. Either catch and decorate it, or set HSTS at the zone edge. **UNVERIFIED** whether the production hostname is a Cloudflare zone or `*.pages.dev`.

**vmb-api** serves JSON only, so the [OWASP REST cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html) set applies: `Cache-Control: no-store`, `Content-Security-Policy: frame-ancestors 'none'`, HSTS, `nosniff` and `X-Frame-Options: DENY`. Hono's `secureHeaders()` covers most of these by default: HSTS `max-age=15552000; includeSubDomains`, `nosniff`, `X-Frame-Options: SAMEORIGIN`, COOP/CORP `same-origin`, `Referrer-Policy: no-referrer`, and no CSP ([Hono docs](https://hono.dev/docs/middleware/builtin/secure-headers)). Override the frame option and add the CSP.

## 5. CSP violation reporting

- **`report-uri` is deprecated** in favour of `report-to`, and is ignored by browsers that support `report-to` ([CSP3 §6.5](https://www.w3.org/TR/CSP3/#directives-reporting); [MDN report-uri](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/report-uri)). MDN advises sending both until `report-to` support is broad.
- **Payload formats differ.** `report-uri` POSTs `application/csp-report` with a `{"csp-report": {…}}` body. `report-to` POSTs `application/reports+json`, an array of `{type: "csp-violation", body: {effectiveDirective, blockedURL, sample, …}}`. Treat both as attacker-controlled ([MDN report-to](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/report-to)).
- **`report-to` needs a `Reporting-Endpoints` header** (`Reporting-Endpoints: csp="https://…/csp-report"`). Support: Chrome 96, Firefox 130, Safari 16.4. CSP `report-to` itself: Chrome 70, Firefox 149, Safari 16.4 ([browser-compat-data](https://github.com/mdn/browser-compat-data/blob/main/http/headers/Content-Security-Policy.json)).
- **Endpoint requirements.** Reporting API endpoints must be potentially trustworthy (HTTPS). Reports are sent with `mode: "cors"` and `credentials: "same-origin"` ([Reporting API §3.2, §3.5.2](https://w3c.github.io/reporting/)). `application/reports+json` is not a CORS-safelisted content type, so a cross-origin endpoint must answer the preflight; this is inferred from the Fetch rules.
- **How SvelteKit exposes this.** `report-uri` and `report-to` are ordinary keys in `directives` and `reportOnly`, and `reportOnly` requires one of them (§1). SvelteKit does not emit `Reporting-Endpoints`, so set it in `handle`.
- **Cheap collection options** (no recommendation):
  1. **A same-origin `+server.ts` POST route in apps/web** (for example `/csp-report`) that logs a size-capped, sanitised summary to Workers logs. It needs no CORS. SvelteKit's CSRF origin check only covers form content types (`x-www-form-urlencoded`, `multipart/form-data`, `text/plain`) ([config docs, `csrf`](https://svelte.dev/docs/kit/configuration#csrf)), so report content types pass. Exclude the route from the auth gate in `isPublicRoute`.
  2. **A Hono route on vmb-api.** It needs a CORS preflight for `WEB_URL` and rate limiting, since it is unauthenticated.
  3. **A hosted CSP and Reporting API collector**, of which several have free tiers, or Cloudflare's Client-side Security (formerly Page Shield) ([Cloudflare CSP reference](https://developers.cloudflare.com/fundamentals/reference/policies-compliances/content-security-policies/)). **UNVERIFIED** which plan includes report collection.

## 6. Class-name and JS obfuscation

OWASP treats obscurity as no control. "Open design… is in contrast to security by obscurity where the security of the software is dependent upon the obscuring of the design itself" ([OWASP Developer Guide, security principles](https://devguide.owasp.org/en/02-foundations/03-security-principles/)). Also: "Developers must never rely on client-side access control checks… client-side logic is often easy to bypass" ([OWASP Authorization cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)).

Mangling Tailwind classes or obfuscating the bundle adds build complexity and makes CSP and report triage harder, and protects nothing that the server-side gate (`hooks.server.ts`, `requireSession` on `/api/master/*`) does not already enforce. What does matter on the client is not shipping secrets or source maps. Only `PUBLIC_API_URL` reaches the build (`vite.config.ts:15`, `env.ts:6`), and it is not a secret.

## 7. pnpm supply-chain hygiene

- **`minimumReleaseAge`.** Added in v10.16.0, measured in minutes, set in `pnpm-workspace.yaml`. The default is **1440 since v11**, so it is already active on pnpm 12.4.1 ([pnpm settings: dependency resolution](https://github.com/pnpm/pnpm.io/blob/main/docs/settings/dependency-resolution.md#minimumreleaseage); [supply-chain security](https://pnpm.io/supply-chain-security)). The built-in default is **non-strict**: pnpm falls back to a too-new version when nothing in range is old enough. Setting it explicitly turns `minimumReleaseAgeStrict` on (since v11.0.0). Recommended: write `minimumReleaseAge: 1440` (or `10080`) explicitly. Use `minimumReleaseAgeExclude` (names, patterns, or `pkg@version`) for urgent fixes.
- **`pnpm audit`.** Since v11 it queries the bulk advisories endpoint and filters by GHSA ID. `--fix` adds `overrides`, and with `minimumReleaseAge` set also adds the patched version to `minimumReleaseAgeExclude`. `pnpm audit signatures` (since v11.1.0) verifies registry ECDSA signatures ([pnpm audit](https://pnpm.io/cli/audit)). CI runs neither today (`.github/workflows/ci.yml`).
- **Build scripts.** `onlyBuiltDependencies`, `neverBuiltDependencies` and related settings were **removed in v11** and replaced by `allowBuilds` ([pnpm build settings](https://github.com/pnpm/pnpm.io/blob/main/docs/settings/build.md#allowbuilds)). The repo already uses `allowBuilds` (`pnpm-workspace.yaml:4-7`). `strictDepBuilds` defaults to `true` (since v10.3.0), so a new unreviewed postinstall script fails the install.
- **Further settings.**
  - `trustPolicy: no-downgrade` (v10.21.0, default `off`) fails an install when a package's provenance or trusted-publisher evidence regresses.
  - `blockExoticSubdeps` (default `true`) keeps transitive dependencies off git and tarball URLs.

  Both are documented in [pnpm dependency-resolution settings](https://github.com/pnpm/pnpm.io/blob/main/docs/settings/dependency-resolution.md#trustpolicy).

- **Subresource Integrity.** SRI lets the browser verify a fetched resource against a hash. Cross-origin use needs `crossorigin` and CORS ([MDN SRI](https://developer.mozilla.org/en-US/docs/Web/Security/Subresource_Integrity)). VMB loads no third-party scripts, styles or fonts (fonts come from `@fontsource-variable/*` and are bundled via `app.css:4-5`), so SRI has no target today. Apply it, plus a CSP host allowance, if a CDN script is ever added.
- **zod's eval probe.** zod 4 probes `new Function("")` unless `jitless` is set. Its own comment notes that "strict CSPs report the caught `new Function` as a `securitypolicyviolation`" ([unpkg zod@4.6.5 `v4/core/util.js:218-230`](https://unpkg.com/zod@4.6.5/v4/core/util.js)). zod runs client-side in VMB (`lib/field-validation.svelte.ts`, the master forms). Set `z.config({ jitless: true })` in client code to keep reports clean.
